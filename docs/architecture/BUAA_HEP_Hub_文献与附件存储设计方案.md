# 北航高能理论物理课题组网站：文献与附件存储设计方案

- 项目：`lm846802297-bit/buaa-hep-lab`
- 设计版本：v1.0
- 日期：2026-10-21
- 目标：在**不要求新增付款方式**的前提下，建立清晰、可维护、可扩展的文献与附件管理流程。
- 范围：产品设计、数据模型、存储路由、权限、安全、免费额度风险、实施与验收；本文不是已部署状态报告。

---

## 1. 设计结论

建议采用“三类资源、两种存储、一个统一入口”的设计：

1. **可检索到的论文：只登记文献信息和规范链接。** 优先保存 arXiv ID、DOI、出版社页面或作者公开版本链接，不重复上传已有公开版本。
2. **组内自行编写的小型 PDF：使用网站内置上传。** 第一阶段将 Cloudflare Workers KV 作为待验证的存储后端，D1 只存元数据。默认单文件上限 15 MiB，并设置较低的总容量软上限。
3. **大型教材、书籍、讲义包和较大的课程资料：使用外部网盘。** 网站登记网盘类型、分享链接、资源说明和访问提示；文件本体不经过 Pages Functions。

三类资源都通过网站统一展示和检索。用户不必先判断技术存储方式，只需选择“论文链接”“本站小文件”或“外部网盘”。

**关键约束：**
- 不把“免费套餐”描述成永久免费保证。
- 不在无法付款时继续尝试 R2 结算，也不填写虚构账单信息。
- 不把大型二进制文件长期堆在 D1 中。
- 不默认将组内材料设为公开链接。
- 不以本站上传方式重新分发没有相应授权的受版权保护书籍或教材。

## 2. 已确认的仓库现状与未确认事项

### 2.1 从当前仓库代码可确认

- 网站前端部署配置位于 `frontend/wrangler.json`，使用 Cloudflare Pages，并绑定 D1 数据库 `DB`。
- API 文件路由位于 `frontend/functions/api/routes/files.ts`。
- 前端上传控件位于 `frontend/src/components/FileField.vue`。
- 上传策略位于 `frontend/functions/api/utils/uploadPolicy.ts`。
- `Env` 类型中已经定义可选的 `FILES_BUCKET?: R2Bucket`。
- 文件接口已有可选 R2 路径；未绑定 R2 时，后端上传限制回退为 1 MiB。
- 前端 `FileField.vue` 允许输入外部 URL，也提供文件上传控件。
- 当前上传接口使用 `/api/files/:id` 形式的站内链接；下载路由已有登录中间件。
- 仓库有一份为 R2 准备的 PR（PR #1）。该 PR 只涉及 R2 配置与文档，不能在未创建 R2 桶的情况下解除线上限制。

### 2.2 仍需在实现前核对

- 线上实际部署的 commit 是否与仓库 `main` 一致。
- Cloudflare 当前账户是否允许在免费计划内创建 Workers KV namespace，以及绑定是否可在现有 Pages 项目中生效。
- 当前 `uploaded_files` 表的生产结构、历史附件数量和数据量。
- 现有资料库、组会、公告等模块如何保存和展示附件 URL。
- 各模块的角色权限约定，以及哪些附件应对公开访客、普通成员、教师或管理员开放。
- 外部网盘在课题组常用网络中的实际可访问性、下载体验和分享规则。

这些事项不能仅凭 GitHub 源码推断，应在预览环境验证。

## 3. 用户侧交互设计

### 3.1 统一入口

新增或整理为一个统一的“添加资源”交互，先选资源类型：

| 资源类型 | 用户需要填写 | 系统处理 |
|---|---|---|
| 论文 / 可公开查找的文献 | arXiv ID、DOI 或论文 URL；标题可自动补全但允许手动编辑 | 保存元数据与规范链接，不上传论文副本 |
| 本站小文件 | 选择 PDF 文件，填写标题、说明、资源分类和可见范围 | 上传到本站对象存储，D1 保存元数据 |
| 外部网盘资料 | 网盘平台、分享链接、标题、说明、访问提示 | 只保存链接和元数据，不代理文件内容 |
| 普通网页 / 数据集 / 软件 | URL、标题、资源类型、说明 | 保存外部链接 |

### 3.2 默认提示文案

在资源选择页面明确展示：

- **论文：**“优先填写 arXiv ID 或 DOI。能通过公开来源获取的论文通常不必重复上传。”
- **本站小文件：**“适合组内自行编写的短讲义、笔记、公式表和小型 PDF。当前默认上限 15 MiB，具体可用性取决于存储后端和免费额度。”
- **大型资料：**“教材、大部头书籍、课程资料包请先上传至获准使用的网盘，再粘贴分享链接。”
- **权限提醒：**“上传或分享前，请确认你有权分发该文件。内部材料不要设置为任何人可访问。”

前端显示的最大文件大小必须来自后端配置或与后端保持一致，不能在没有 KV/R2 绑定时仍显示“最大 15 MB”。

### 3.3 资源列表卡片

统一卡片建议显示：

- 标题、作者 / 上传者、年份（可用时）；
- 资源类型标签：`arXiv/DOI`、`本站附件`、`外部网盘`；
- 访问范围标签：`公开`、`组内`、`受限`；
- 文件大小（本站附件）、外部平台名称（网盘资源）；
- “打开论文”“下载附件”或“打开网盘”动作；
- 创建时间、最后更新时间；
- 链接有效性状态仅在系统实际验证后显示，不应凭 URL 格式猜测“有效”。

保留已有 URL 输入功能，保证旧数据和旧界面继续可用。

## 4. 存储路由规则

### 4.1 论文链接优先

建议保存的论文字段：

- `arxiv_id`：例如 `2401.01234`，不带 `https://` 前缀；
- `doi`：保存 DOI 本体，规范化后可生成 `https://doi.org/...`；
- `canonical_url`：用户指定或系统生成的规范链接；
- `alternate_url`：作者主页、机构仓储或其他合法公开版本链接；
- `title`、`authors`、`year`、`abstract`：允许为空，不能因为外部元数据服务失败就阻止手工保存。

生成链接时要做输入校验，避免将任意文本直接拼入 URL。arXiv ID、DOI 和普通 URL 应分别校验。文献链接失效时允许管理员更新链接，而不是要求用户重新上传 PDF。

### 4.2 本站小文件

建议第一阶段：

- 默认最大单文件大小：15 MiB（15 × 1024 × 1024 bytes）。
- 仅接受业务确实需要的类型，首批可包括 PDF、PNG、JPEG、WebP、PPT/PPTX、DOC/DOCX；若主要目标是小型自编 PDF，初版可以更严格地只允许 PDF。
- 必须检查扩展名、声明的 MIME type 和文件头；不能只相信浏览器提供的 `file.type`。
- 对 PDF 可做 `%PDF-` 文件头检查，但这不是完整的恶意内容扫描。
- 文件内容存储在 KV；D1 保存元数据和权限。
- KV 免费存储总量暂定软上限 700 MiB，作为安全余量而非平台硬限制；管理员可在实测后调整。
- 上传必须登录。谁可以上传、谁可以删除、谁可以读取，按资源权限执行。
- 不开放匿名写入，不提供可猜测的存储 key。

**Workers KV 目前只作为待验证方案，不是已启用功能。** Cloudflare 官方文档列出的免费计划额度包括：1 GB 存储、每天 100,000 次读取、每天 1,000 次写入；单个值最大 25 MiB。超限后相关操作会失败，不应假设会自动扩容或自动收费。官方文档同时说明 KV 是最终一致性存储，写入后在不同位置的可见性可能延迟。

官方资料：
- https://developers.cloudflare.com/kv/platform/limits/
- https://developers.cloudflare.com/kv/platform/pricing/
- https://developers.cloudflare.com/kv/reference/faq/

因此，正式采用 KV 前必须验证：
1. 当前 Cloudflare 账户能否在不填写付款信息、不升级套餐的情况下创建 namespace；
2. 现有 Pages Functions 能否绑定 namespace；
3. 上传后立即下载、跨区域访问、覆盖和删除的实际表现；
4. 免费额度用尽时系统是否能清楚报错，且不损坏元数据；
5. 是否能在不影响现有附件的前提下回滚。

如果 KV 不能启用，先退回外部网盘路线；不应自动将 15 MiB 文件塞入 D1。

### 4.3 大型教材、书籍和课程材料

- 文件本体存储在用户选择的外部网盘。
- 网站保存平台名、分享链接、标题、说明、资源分类和访问提示。
- 第一阶段不接入 Google Drive、OneDrive、百度网盘、夸克网盘、阿里云盘、腾讯微云、Dropbox、Box 等服务的 OAuth 或上传 API；只把它们当作可替换的链接提供方。
- 不将分享链接的存在误认为文件永久有效；管理员可以标记链接失效并更新。
- 不建议将分享提取码明文放在公开页面或普通数据库字段。若未来要在站内保存提取码，必须先设计密钥管理和加密方案；初版可要求用户在网盘页面输入提取码。
- 不把网盘挂载为公开匿名文件代理，不绕过服务商的访问限制。

候选平台（容量、单文件限制、下载体验和分享政策都可能变化，必须以当前账户实测为准）：

| 平台 | 适用定位 | 注意事项 |
|---|---|---|
| 夸克网盘 | 国内成员分享大文件的候选 | 测试分享链接有效期、提取码、登录要求与下载体验 |
| 阿里云盘 | 国内成员分享资料的候选 | 核实免费容量、分享规则和当前账号能力 |
| 百度网盘 | 国内用户覆盖较广的备选 | 核实下载限制、分享有效期及 API 条件 |
| 腾讯微云 | 国内补充候选 | 核实免费额度与链接访问体验 |
| Google Drive | 国际协作及外部合作备选 | 容量与 Gmail、Google Photos 等服务可能共享；确认国内网络可用性 |
| OneDrive | 使用 Microsoft 账户的成员 | 免费空间较小；核实共享链接和账户政策 |
| Dropbox / Box / pCloud | 国际备选 | 免费容量、单文件上限、共享流量和地区可用性各不相同 |

**不要因为某个网盘提供免费容量，就假设其适合保存全部科研资料。** 先用 2–3 个实际账户测试，再确定默认推荐平台。

## 5. 数据模型建议

### 5.1 原则

- 先做增量迁移，不删除或重建生产表。
- 资源元数据与文件二进制分离。
- 所有新增记录必须有明确的资源类型、存储后端和访问范围。
- 不在每次上传请求中执行 `ALTER TABLE`；数据库变更通过版本化 migration 一次执行。
- 旧的 `/api/files/:id` 链接继续有效。

### 5.2 统一资源表（建议）

建议新增 `resource_items`，用于论文、本站附件、网盘链接和其他 URL 的统一索引。以下为逻辑字段草案，具体 SQL 类型和索引需根据现有 schema 核对后确定：

| 字段 | 含义 |
|---|---|
| `id` | UUID 或稳定唯一 ID |
| `resource_type` | `paper_link` / `site_upload` / `external_drive` / `web_link` |
| `title` | 资源标题 |
| `description` | 说明 |
| `authors` | 作者信息，可空 |
| `year` | 年份，可空 |
| `arxiv_id` | arXiv ID，可空 |
| `doi` | DOI，可空 |
| `canonical_url` | 规范链接 |
| `alternate_url` | 备用链接，可空 |
| `provider` | 外部网盘名称，可空 |
| `external_url` | 网盘分享链接，可空 |
| `file_id` | 指向现有 `uploaded_files.id`，仅本站附件使用 |
| `visibility` | `public` / `group` / `restricted` |
| `owner_user_id` | 创建者 ID |
| `created_at` / `updated_at` | 时间戳 |
| `deleted_at` | 软删除时间，可空 |
| `status` | `active` / `pending` / `unavailable` / `deleted` |

如现有模块已经有可复用的资源表，应优先扩展现有结构，而不是重复造表。

### 5.3 现有 `uploaded_files` 表的增量扩展

当前文件路由已经使用 `uploaded_files` 保存文件名、类型、大小、哈希、创建时间，且可选地将内容保存到 R2 或 D1。采用 KV 时建议增加：

- `storage_backend`：`d1_legacy` / `kv` / `r2`；
- `storage_key`：KV/R2 中的不可预测对象 key；
- `uploaded_by`：上传用户 ID；
- `visibility`：文件访问范围；
- `upload_status`：`pending` / `ready` / `failed`；
- `sha256`：文件哈希，保留已有去重能力；
- `last_accessed_at`：可选，只有确实需要时再增加。

不要把 KV 对象 key、外部分享提取码或凭据暴露给不应访问的客户端。

### 5.4 为什么不直接把所有文件存进 D1？

D1 适合元数据、关系查询、权限和索引；把大文件写成 BLOB 会消耗数据库容量，并增加行读取/写入压力。D1 分块方案只适合作为经过容量计算和故障测试后的临时备选。初版不要同时实现 KV、D1 分块和 R2 三套新存储路径，以免增加迁移与故障面。

## 6. API 与前端改动

### 6.1 建议的 API 形态

以下是设计目标，不代表这些端点已经实现：

- `GET /api/resources`：按关键词、资源类型、年份、可见范围筛选资源；
- `POST /api/resources`：创建论文链接、网盘链接或普通 URL 资源；
- `PATCH /api/resources/:id`：更新标题、说明、链接和可见范围；
- `DELETE /api/resources/:id`：软删除资源记录；本站附件是否物理删除按权限与保留策略处理；
- `POST /api/files`：本站文件上传，需登录和权限校验；
- `GET /api/files/:id`：保留兼容性，读取旧 D1 文件或新 KV 文件；
- `DELETE /api/files/:id`：仅对有权删除的文件开放，并同步处理对象和元数据。

### 6.2 前端组件

建议逐步整理 `frontend/src/components/FileField.vue`：

1. 保留当前 URL 输入框，避免破坏现有表单。
2. 将上传按钮文案改为“上传本站小文件（上限以服务器配置为准）”。
3. 添加“添加论文链接 / 添加网盘链接”的入口，或复用现有资源表单。
4. 显示文件大小、类型、上传状态和可见范围。
5. 超过本站限制时，给出明确的替代路径：“请使用外部网盘并粘贴分享链接”，而不是只提示失败。
6. 对 arXiv ID 和 DOI 做输入校验，并允许用户手工修改自动生成的链接。
7. 网盘链接打开时使用明确的外部链接提示；不要在未经验证的情况下承诺可直接预览或免登录下载。

### 6.3 外部链接的验证策略

初版不应由后端随意抓取用户提交的任意 URL，否则可能产生 SSRF 风险。第一阶段只做：
- URL 语法验证；
- 限制 `http` / `https` 协议；
- 显示用户提交的域名；
- 在用户点击时由浏览器打开外部链接；
- 可选的人工“测试链接”功能应采用域名白名单和安全的服务器端网络策略。

不要让后端直接请求任意 URL 来判断链接是否有效。

## 7. 权限、隐私与版权

### 7.1 资源访问范围

| 范围 | 建议行为 |
|---|---|
| `public` | 任何访客可查看元数据；本站文件可公开读取的前提是内容确实适合公开 |
| `group` | 需要登录并属于课题组；后端每次读取文件时验证身份和成员资格 |
| `restricted` | 仅资源所有者、授权教师或管理员等明确授权人员访问 |

前端隐藏按钮不是安全措施。服务端的文件读取接口必须执行权限检查。

### 7.2 版权与科研资料

- 论文优先链接到 arXiv、DOI、出版社或机构仓储中合法可访问的版本。
- 对出版社付费论文，不因网站有文件上传能力就默认上传或公开全文。
- 大型教材、书籍仅存放合法获取并有权共享的资料；购买过某本书不自动意味着可以向全组公开分发电子副本。
- 未公开论文草稿、审稿意见、研究数据和个人信息默认使用受限权限。
- 不在日志中记录密码、提取码、访问令牌或文件内容。
- 公开资源和内部资源应在 UI 上清楚区分，避免误操作。

## 8. 配额与失败处理

### 8.1 初始配额建议

以下是产品层面的保守初始值，应在实际账户额度确认后调整：

- 单文件：15 MiB；
- KV 附件总量软上限：700 MiB；
- 单用户每日上传量：初始可设 50 MiB；
- 只允许经过验证的文件类型；
- 预留至少 30% 的存储空间给元数据、迁移余量或后续需要；
- 管理员页面显示附件总量、最近上传失败、待清理对象和外部链接状态。

不要把这些应用层限额误称为 Cloudflare 的官方限制。

### 8.2 失败情形

| 失败情形 | 预期处理 |
|---|---|
| 未登录上传 | 返回 401/403，不创建对象 |
| 文件过大 | 返回 413 或业务错误，提示外部网盘替代方案 |
| 文件类型不支持 | 返回 415，不写入存储 |
| KV namespace 未绑定 | 禁用本站上传并提示外部网盘；不能悄悄把大文件写入 D1 |
| KV 写入成功但 D1 元数据失败 | 尝试删除对象；若清理失败，记入可审计的待清理记录 |
| D1 元数据存在但 KV 对象缺失 | 返回明确的存储缺失错误，管理员可修复或更新链接 |
| KV 超出免费写入/读取额度 | 返回可理解的暂时不可用提示，不自动触发付费升级 |
| 外部网盘链接失效 | 资源保留但标记待更新，不删除文献信息 |
| 权限不足 | 返回 403；不要泄露文件是否存在以外的敏感元数据 |
| 删除本站文件 | 检查权限、软删除元数据、清理对象并记录结果 |

Workers KV 的免费额度包含每日读写上限，超限后相关操作会失败；因此必须将额度不足当作可预期的运行故障处理，而不是依赖自动付费。具体数值以 Cloudflare 官方当前页面为准。

## 9. 测试与验收

### 9.1 功能验收

- [ ] 输入 arXiv ID 可保存并生成规范链接；
- [ ] 输入 DOI 可保存，非法 DOI 不生成错误链接；
- [ ] 允许手工添加普通论文 URL；
- [ ] 添加外部网盘链接时不上传文件本体；
- [ ] 本站上传路径仅在存储后端可用时启用；
- [ ] 1 MiB 以下、5 MiB、15 MiB 文件按配置正常处理；
- [ ] 超限文件给出网盘替代方案；
- [ ] 旧的 `/api/files/:id` 链接仍可访问；
- [ ] 旧 D1 BLOB 附件可正常读取；
- [ ] 文件名含中文、空格和特殊字符时，下载文件名正确；
- [ ] 删除和替换附件不会留下不可追踪的对象；
- [ ] 资源列表可以按类型和可见范围筛选。

### 9.2 安全验收

- [ ] 未登录用户无法上传；
- [ ] 普通成员无法读取 `restricted` 文件；
- [ ] 修改 URL 中的文件 ID 不会绕过权限；
- [ ] 服务端验证文件大小，不只依赖前端；
- [ ] MIME type 与文件头校验已实现；
- [ ] 不接受 `javascript:` 等非 HTTP(S) 外部链接；
- [ ] 不把外部 URL 交给无保护的服务端抓取器；
- [ ] 不在公开 API 响应中泄露 KV key、令牌或提取码；
- [ ] 上传失败时数据库与对象存储状态可恢复；
- [ ] 达到总容量限制后不再接受新文件，但链接资源仍可正常使用。

### 9.3 运行与额度验收

- [ ] 在 Cloudflare 控制台确认当前套餐和 KV namespace 是否可用；
- [ ] 不要求新增付款方式，不升级付费计划；
- [ ] 上传后立即下载和跨区域读取已实测；
- [ ] 模拟 KV 不可用、D1 写入失败和容量不足；
- [ ] 验证免费额度用尽时不会自动产生预期外账单；
- [ ] 部署前备份 D1，且不在生产请求中执行 schema 变更。

## 10. 分阶段实施计划

### 阶段 0：冻结高风险操作

- 暂停 R2 付款流程。
- 保留现有 R2 PR，不合并、不部署。
- 确认生产分支和生产数据库当前状态。
- 对 D1 做备份，盘点现有附件。

**退出条件：** 明确当前线上版本、附件表结构、权限规则和可回滚方案。

### 阶段 1：外部网盘工作流

- 规范外部资源类型与 URL 字段；
- 添加网盘平台选择和访问提示；
- 统一“论文链接 / 本站小文件 / 外部网盘”的交互；
- 修正前端 15 MiB 默认提示与后端 1 MiB 实际限制不一致的问题；
- 测试夸克、阿里云盘、百度网盘、腾讯微云以及用户已有的国际网盘账户。

**退出条件：** 不依赖新增付款方式，组员能保存并打开外部网盘链接，旧链接继续工作。

### 阶段 2：验证 Workers KV 可用性

- 仅在 Cloudflare 控制台尝试创建测试 namespace；
- 不输入虚构账单信息、不升级套餐；
- 验证免费计划绑定与实际限制；
- 用测试数据完成写入、读取、删除和额度错误模拟。

**退出条件：** 确认能免费使用且技术行为满足要求；否则停止 KV 开发，继续采用阶段 1。

### 阶段 3：本站小文件上传

- 新建独立分支；
- 添加 KV 绑定和元数据 migration；
- 实现存储适配层，区分 `d1_legacy`、`kv`、未来的 `r2`；
- 实现上传、下载、权限校验、容量限制和失败清理；
- 加测试并在预览环境验证。

**退出条件：** 功能、安全、兼容性和额度测试全部通过。

### 阶段 4：上线与观察

- 先小范围开放给管理员或教师测试；
- 监控附件总量和失败率；
- 验证备份与恢复；
- 再开放给普通成员；
- 当 KV 容量接近软上限时，优先将大文件转移到外部网盘，而不是自动升级套餐。

## 11. 风险与决策记录

| 事项 | 当前判断 | 决策 |
|---|---|---|
| R2 需要付款信息 | 用户当前无法提供可用付款方式 | 不继续 R2 付款流程 |
| 外部网盘 | 最快可用，不需网站端新增存储后端 | 第一阶段实施 |
| Workers KV | 有免费额度，单值上限高于 15 MiB，但最终一致性且每日操作受限 | 先验证，再决定是否实现 |
| D1 BLOB | 已用于兼容旧附件，但不适合作为大文件主仓库 | 仅保留旧文件兼容 |
| D1 分块 | 技术上可做，但增加数据库负载和维护复杂度 | 暂不作为首选 |
| 版权和访问控制 | 直接影响科研资料安全 | 作为上线阻断验收项 |
| 免费承诺 | 免费计划可能变化或用量超限 | 只承诺“尽量控制在免费额度内”，不承诺永久免费 |

## 13. 最终建议

不要把这个功能做成“所有文件都上传到同一存储桶”的通用文件仓库，而应让存储方式符合科研资源的性质：

- **可检索的论文 → arXiv / DOI / 官方链接；**
- **组内自编的小型 PDF → 网站内上传（Workers KV 通过免费可用性验证后启用）；**
- **大型教材、书籍和课程包 → 外部网盘链接；**
- **敏感或未公开科研材料 → 受限访问，不因存储方便而公开。**

这能最大限度减少重复文件、降低存储需求，并让网站在不新增付款方式的情况下继续发展。本文是设计方案，尚未代表 KV 已创建、代码已修改或网站已部署。
