## 0. 结论摘要

**已决定采用“左侧研究介绍 + 右侧真实科学图片 + 下方四张研究方向卡片”的首页布局，但不原样照搬示意图。** 视觉令牌遵循根目录 `design.md` 的 Quiet Research 规范，不再将旧版深青/海军蓝作为默认主题；去掉示意图外围的白色圆角框；用经过来源与许可核验的 ATLAS/CERN 事件显示图替换抽象碰撞 SVG。桌面端采用左右双栏，手机端改为单列顺序布局。

当前公开首页已经具备完整的信息架构：导航、Hero、研究方向、代表论文、物理资源、关于我们、组内协作入口和页脚。论文区已有搜索、主题筛选、年份筛选、排序、arXiv/INSPIRE/DOI 链接、复制引用和 BibTeX 导出等功能，应继续保留。

最值得优先处理的事项：

1.  用有明确来源和授权的真实 ATLAS/CERN
    事件显示图替换首页抽象的同心圆碰撞 SVG。
2.  让 Hero 更紧凑，减少无必要的空白，清晰安排标题、简介、按钮和图片。
3.  修复论文列表桌面网格中没有对应内容的第三列。
4.  统一图片本地化、署名、许可、替代文本和失败回退。
5.  沿用 Quiet Research 的克制学术风格，不增加无必要的
    3D、持续粒子动画或复杂滚动特效。

### 已确认的设计决策（2026-10-21）

本轮已确认采用先前讨论的首页布局作为改版目标，具体约束如下：

1. **整体结构采用，细节不照搬。** 桌面首页的 Hero 左侧放研究定位、简短简介和两个 CTA；右侧放真实科学事件图及来源说明。Hero 之后紧接 `RESEARCH AREAS` 区域，以四张卡片展示暗物质与暗扇区、中微子与新相互作用、希格斯与新标量、对撞机唯象学。
2. **遵循全站 Quiet Research 设计令牌。** 使用 `design.md` 定义的纸白背景、墨色正文、陶土橙强调色、衬线主标题与实体卡片。不要把网站包在示意图的白色圆角外框里；页面保持全宽布局，但不使用旧版深色背景作为默认主题。
3. **保留现有功能和导航。** 导航应继续覆盖研究方向、论文成果、物理资源、关于我们和组内协作；不能因为简化 Hero 而删除资源导航或内部工作台入口。
4. **主图必须是真实且可追溯的素材。** 首选评估 CERN/ATLAS 官方事件显示图，下载后核对具体文件、原始记录、许可和署名，再存入本地静态资源目录。图片尚未下载、授权尚未核验时，只能保留占位框，不能把占位图当作最终成果。
5. **图片不承担网页文字的职责。** 不把“Collider Event Display”、研究方向列表、按钮或许可说明烧录进图片；这些信息应由 HTML 文本呈现。图注要说明这是 ATLAS/CERN 的实验事件显示示例，不代表北航课题组自有实验数据，也不暗示课题组属于 ATLAS 合作组。
6. **移动端使用独立的单列布局。** 顺序为：导航 → 标题 → 简介 → CTA → 图片 → 图片来源说明 → 研究方向卡片。避免图片先占满屏幕，或让标题、按钮和研究方向被推得过远。
7. **优先完成最小改版。** 第一轮只改 Hero、研究方向卡片的衔接、论文列表空白列和图片资源管理；代表论文、物理资源、关于我们、组内协作与页脚继续沿用现有实现，避免一次重写整个首页。

这组决策是本方案后续实现和验收的基准；如果开发中要改变主图类型、导航内容或首屏结构，应先更新本节，再同步修改验收清单。

### 审查边界

本方案依据可读取的 GitHub `main` 分支源码和仓库内
`docs/audit/实施与验收报告.md`
制定。当前环境未能成功读取线上网页的实际渲染，因此：

-   **已确认：** Vue
    组件、CSS、路由、内容数据，以及仓库报告中记录的实现和测试结果。
-   **尚未确认：** 线上部署版本是否与当前 `main` 完全一致、CDN
    上实际图片的加载状态和所有浏览器的视觉差异。
-   **未执行：** 本方案没有修改网站源码、提交 GitHub、修改 Cloudflare
    配置或部署。

## 2. 目标视觉方向

### 2.1 设计关键词

-   **学术：** 看起来像真实的理论物理研究组网站，而不是科幻游戏或商业
    SaaS 产品页。
-   **科学：** 使用有出处的事件显示、实验装置图或经审核的理论示意图。
-   **克制：**
    控制渐变、发光、阴影和动效，不让装饰抢占论文内容的注意力。
-   **可追溯：** 科学图片和论文均有来源、许可、状态与核查记录。
-   **响应式：**
    桌面、平板、手机均可阅读；公式、论文标题和筛选控件不溢出。

### 2.2 沿用现有设计变量

  用途          方案
  ------------- ----------------------------------------------
  背景          使用 `design.md` 定义的 `--bg`（默认纸白）
  主文字        沿用 `--text`
  正文/说明     使用 `--soft`、`--muted`，并验证对比度
  强调色        沿用 `--accent`
  分隔线/卡片   沿用 `--line`、`--surface`
  图片边框      1px 低对比度边框，圆角 12--16px
  阴影          仅用于需要层次的组件，不为每张卡片添加厚阴影

不建议改成高饱和霓虹、游戏式
HUD、大面积玻璃拟态；不要把标题、公式和大段文字直接烧录到图片。公开首页与工作台共享 Quiet Research 语义令牌，但不机械复制内部工作台的可选背景素材或动态效果。

### 3.5 图片首选与替代

**首选候选：ATLAS-PHOTO-2026-016，希格斯玻色子通过矢量玻色子融合产生并衰变为双光子的候选事件显示（(H\\to\\gamma\\gamma)）。**

4.0。正式发布前仍应从原始记录确认所下载的具体文件与许可对应一致。

图片使用规则：

1.  从 CERN 原始记录下载，确认图片文件、图注和许可属于同一条记录。

2.  存入 `frontend/public/images/`，避免上线时依赖 CERN 外部服务器。

3.  可生成 WebP/AVIF 派生版本，但保留原文件及来源记录。

4.  裁剪不得改变物理含义或去掉关键标签。

5.  推荐图注：

    > ATLAS
    > 事件显示示例：矢量玻色子融合产生的希格斯玻色子候选事件，(H\\to\\gamma\\gamma)。来源：ATLAS
    > Collaboration / CERN，ATLAS-PHOTO-2026-016，CC BY
    > 4.0。用于说明对撞机事件可视化；不代表本课题组自有实验数据或 ATLAS
    > 合作组身份。

6.  提供准确 alt，例如："ATLAS
    探测器中矢量玻色子融合产生的希格斯玻色子候选事件显示，末态为两个光子。"

7.  图片来源和许可须作为可读文本，不只放在 hover tooltip。

8.  维护图片清单：文件名、原始
    URL、许可、署名、下载日期、裁剪状态、替代文本。

首选图与希格斯和对撞机唯象学联系明确，但不能直接代表暗物质或中微子方向；其他方向应通过文字和研究卡片呈现，不能暗示一张图代表全部研究内容。

## 4. 研究方向区

当前研究方向区已有方向标题、研究问题、主要方法、实验联系、补充说明、标签、相关论文和"查看相关论文"入口。这套内容结构适合高能理论物理网站，应保留。

建议： - 桌面端继续采用左侧方向列表、右侧详情卡片。 -
当前方向用文字、边框或图标等多重方式提示，不只改变颜色。 - "研究问题 /
主要方法 / 实验联系"使用稳定的标签和正文层级。 -
相关论文只展示少量最相关条目，并提供查看全部相关论文的入口。 -
手机端继续单列排列；如果未来方向数量明显增加，再考虑可折叠列表。 - 保留
`ArrowUp`、`ArrowDown`、`Home`、`End` 键盘操作与焦点同步。 -
仅将课题组确认的方向作为首页主方向。暗物质、中微子/NSI、希格斯/新标量、对撞机唯象学、相变与引力波、对撞机精度/量子计量学可作为候选标签；是否全部成为一级方向应由课题组确认。

## 5. 代表论文区

### 5.1 保留已有功能

保留主题筛选、关键词搜索、年份筛选、排序、出版状态、期刊/DOI、arXiv/INSPIRE
链接、复制引用和 BibTeX 导出。不另建独立文献系统。

### 5.2 已确认的布局问题

论文条目的模板包含两个直接网格子元素：`.paper-year` 和
`.paper-content`；但 CSS 设置了
`grid-template-columns:82px 1fr 80px`。没有第三个对应子元素，因此桌面端会预留一个空白第三列。

建议修复为：

``` css
.public-paper {
  display: grid;
  grid-template-columns: 82px minmax(0, 1fr);
  gap: 28px;
}
```

如果将来需要独立的操作栏，应先在模板中添加真实的第三列内容，再定义三列网格。手机端继续使用约
`50px minmax(0, 1fr)`，并检查长标题、作者、DOI 与 arXiv 编号的换行。

### 5.3 推荐条目层级

``` text
2026       [暗物质 / 已发表]
           论文标题（主信息）
           作者列表
           1–2 句经审核的研究摘要
           期刊、卷页或文章编号 · DOI
           arXiv ID · 元数据核查日期
           [arXiv] [INSPIRE] [复制引用]
```

-   标题是主信息；作者和出版信息为次级信息。
-   控制标签数量，不要用满屏彩色标签。
-   "已发表"与"预印本"必须用文字区分，不能只靠颜色。
-   DOI、作者列表和长标题允许换行。
-   搜索框在桌面端与筛选并排，在手机端占满容器宽度。
-   分类按钮可换行；不能只用不明显的横向滚动来隐藏选项。
-   无结果状态应提供清除筛选的操作。
-   复制引用失败时提供回退方式。

### 5.4 文献维护

继续用 `frontend/src/content/lab.js` 作为公开内容白名单。每条记录保留
arXiv/DOI/INSPIRE
来源和最后核查日期。自动抓取只能生成待审核草稿；正式出版状态、作者、标题和
DOI
需交叉核对。代表论文不是完整论文列表，合作作者的全部论文也不能自动视为课题组独立成果。

-   每张卡片保留名称、类别、简短用途说明和外链。
-   不在首页嵌入第三方网站内容，不加载第三方追踪脚本。
-   明确这是资源导航，不代表课题组托管或背书第三方服务。

## 8. 性能、SEO 与可访问性

仓库中的 `docs/audit/实施与验收报告.md`
已记录路由拆分、重型依赖按需加载、初始 JS 预算、浏览器检查和 SEO
相关实现。本次不把这些工作误标为完全缺失；图片与版式改动后应做回归测试。

### 图片与性能

-   Hero 图使用本地静态资源，例如
    `/images/atlas-higgs-vbf.webp`，不在生产页面依赖 CERN 实时加载。
-   Hero 图提前设置宽高比，避免布局偏移；首屏图片可优先加载。
-   低于首屏的图片才使用懒加载；没有真实用途的地方不要为装饰而加图。
-   图片失败时使用 `var(--surface)` 或 `var(--panel-solid)` 作为回退，并提供文字说明。
-   不使用多重滤镜和大面积模糊替代图片优化。

### SEO 回归

当前 HTML 已有 canonical、description、Open Graph、Twitter
元数据；仓库报告还记录了预渲染、结构化数据、robots 与 sitemap
的工作。改版后需要复核而不是盲目重做： -
分享卡片的标题、摘要和图片正确； - canonical 指向正确生产 URL； -
内部入口不会被误当作公开研究内容； -
公开专题若变成独立路由，应有独立标题和描述； - `noindex` 不是访问控制。

### 可访问性

-   键盘焦点清晰，导航、选项卡、输入和筛选均可操作。
-   ARIA 状态与可见状态一致。
-   图片有准确 alt，图片来源/许可是可读文本。
-   重要文本对比度达到 WCAG AA 的常规文本目标。
-   正文和输入字号不应过小；关键说明不使用 10--11px。
-   遵守 `prefers-reduced-motion: reduce`。
-   200% 缩放后仍可完成主要操作。

### 视口验收矩阵

  视口        重点
  ----------- ----------------------------------------
  320×640     最窄手机；导航、标题、按钮、DOI 不溢出
  360×800     Hero 图不挤压文字
  390×844     研究方向与论文卡片阅读顺畅
  768×1024    平板导航与双列不过度拥挤
  1024×768    Hero 比例与筛选布局合理
  1440×900    内容宽度受控
  1920×1080   大屏内容不被无限拉宽

## 9. 实施优先级

### P0：改版前确认

1.  确认官网名称与公开身份描述。
2.  核对图片来源、具体文件和许可。
3.  核对线上部署版本与 GitHub `main` 的关系。
4.  不改变内部数据权限边界。

**验收：** 公开身份信息已确认；图片授权可追溯；图注不会暗示课题组属于
ATLAS/CMS 合作组。

### P1：优先实施

1.  替换 Hero 抽象 SVG 为 ATLAS/CERN 官方事件显示图。
2.  调整 Hero 高度与左右列比例，减少无意义留白。
3.  修复论文列表的空白第三列。
4.  增加图片本地化、压缩、署名清单和失败回退。
5.  检查长标题、作者、DOI 和筛选控件换行。
6.  确认初始 JS 预算和路由拆分没有回退。

**验收：**
图片有来源和许可说明且不拉伸；论文列表无空白列；手机无非必要横向溢出；构建预算通过。

### P2：内容呈现

1.  加强研究方向与相关论文的互链。
2.  梳理论文出版状态、期刊信息与摘要的视觉层级。
3.  完善资源卡片用途和外链可发现性。
4.  做焦点、对比度、图片 alt、200% 缩放检查。
5.  复核标题、分享卡片和 canonical。

### P3：可选增强

-   只有在有维护能力时才增加完整英文版本。
-   专题页需有已核验的论文与内容负责人。
-   可使用课题组原创的理论示意图，但需标明模型与图示性质。
-   暂不增加 3D
    粒子背景、实时访客统计、过多动画或未经审核的自动论文发布。
